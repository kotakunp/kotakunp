## Dependency notes

- **004 requires 001**: the audio player renders inside the release detail
  route and extends `ReleaseDetail` from `src/content/release-details.ts`,
  both created by 001.
- **006 requires 001**: its `opengraph-image.tsx` sits beside the
  `[lang]/music/[slug]` route created by 001.
- **007 requires 002**: the subscribe route imports `rateLimit` from
  `src/lib/rate-limit.ts`, created by 002.
- **Shared file — `src/app/[lang]/layout.tsx` is modified by 005, 006, AND
  008**: execute them in the order **005 → 006 → 008**. 008's Step 2 is
  written to tolerate either order (it skips layout image rewrites when 006
  already removed them), but the recommended order avoids churn entirely.
- **Shared file — `src/app/[lang]/music/page.tsx` is modified by BOTH 001
  (filters + featured links) and 007 (newsletter form swap)**: land 001
  before 007, or expect textual conflicts in that file.
- Everything else is independent; 001/002/003 can proceed in parallel.
- **010 is intentionally self-contained**: it replaces both the MDX journal and
  handwritten release/track modules with a first-party SQLite/Drizzle studio
  for writing and on-site music publishing. It leaves the message wall and
  subscriber NDJSON APIs alone and must not be implemented with a CMS.

## Findings considered and rejected

- **Migrating the message wall / subscribers to a database**: rejected for now
  — single-instance static deployment, NDJSON is adequate, and the dictionary
  string `reachOut.prototypeNote` already documents the constraint. Revisit at
  first serverless/multi-instance deploy.
- **Per-locale journal posts**: rejected for now — all three posts are
  English-only by authoring choice; forcing locale plumbing adds structure
  with no content to serve. Revisit if/when translated posts exist.
- **Adopting Payload or another CMS for content/music publishing**: rejected — this
  project intentionally owns a narrow single-author backend so its maintenance
  and security surface match the actual feature set rather than a CMS platform.
- **AVIF image variants alongside WebP**: rejected — encode time and dual-file
  complexity outweigh the marginal savings over q82 WebP at these sizes.
- **Site-wide persistent "now playing" widget**: deferred, not rejected —
  plans/004 builds the self-contained `AudioPreview` component first; a
  global player is a larger design decision the maintainer should make after
  real audio assets exist.
